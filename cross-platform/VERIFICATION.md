# Verification — 10 November 2026

## 0.2.1 — studio camera repair

- Reproduced the original failure on the installed 0.2.0 APK: horizontal drag gave exactly zero mean pixel change in the rendered viewport. A drag before placement also incorrectly placed a model.
- Replaced the orientation-driven orbit camera with an explicitly positioned and aimed camera. React Native touch gestures control spherical orbit/elevation and bounded zoom. Short taps place; drags, multi-touch and long presses do not. Reset and scrollable camera buttons provide alternatives to gestures. Models remain in their existing scene coordinates.
- Twenty-one TypeScript tests pass, including seven camera/gesture cases: camera aim, orbit limits, zoom limits, tap-vs-drag, long presses, pinch and one/two-finger transitions. The existing fourteen tests remain green. Type checking and all four Python geometry/package checks pass.
- Native `tools/qa_studio_camera.py` passes on the final APK: horizontal and vertical drags, zoom in/out buttons, a real two-pointer pinch, exact reset, no accidental placement, camera movement during burning, and movement around spent remnants without relighting. The emulator-only Java input helper initially used a context-dependent InputManager API; changing it to Android 14's InputManagerGlobal fixed the test harness. This helper is not included in the application.
- Screenshot comparisons measure the rendered scene, rather than only a JS camera state. Final mean RGB differences: horizontal drag 13.02, elevation 31.79, zoom 8.48, pinch 22.85; reset difference 0.00. Results and the exact APK SHA256 are in `dist/qa-studio-camera.json`; screenshots are in `dist/screenshots/camera/`.
- Visual review exposed a clipped model base behind the taller tray. The studio now occupies the measured space between header and tray. Viro 2.52's navigator discards its incoming style via a comma expression, so sizing is applied to a parent View. The final default screenshot shows the complete cone and base within the viewport.
- A final chakri smoke check passed placement, complete model loading, ignition, completion, spent-state gating and clear on the same APK. Its placed/spent screenshots confirm the flat coil remains fully visible above the tray. The short burn was already spent by the automated "burning" screenshot; that image is not claimed as a captured active flare. `dist/qa-smoke.json` records this check and matches the camera report's APK SHA256.
- Final Android release compilation and APK v2 signature verification pass. App version is 0.2.1, Android version code 2, with the existing package ID and test signing key so it installs as an update.
- The final iOS JS/Hermes export passes (763 modules, 111 resources). iOS native compilation, signing and physical-device checks remain unperformed.

The following results describe the original 0.2.0 implementation and its six-effect baseline; they are not a claim that six full flows were rerun for every camera-only build.

## 0.2.0 — original implementation

- Fourteen TypeScript checks passed: thirteen state/timeline/transform/readiness/platform/particle-direction checks and one dependency-archive patch check. New behavior was observed failing before implementation. Coverage includes anchor gating, tracking loss, stale callbacks, spent-anchor retention, actual pop cues, consumption, detonation, local transforms, delayed clock samples, external pause, model/audio readiness, platform-specific alignment, and a sky burst that spreads downward as well as upward.
- Three Python geometry tests passed. They check all six generated models, finite vertices and valid triangles, grounding and flat orientation, 36 separate ladi tubes, and outward tube winding for native backface culling. The winding test was observed failing before correction.
- A fourth Python check verifies that every advertised APK architecture contains the native renderer. It failed on the initial mixed-architecture APK and passed after restricting the Android build to ARM64.
- TypeScript type checking passed.
- Expo's iOS Hermes bundle export passed: 763 modules and 111 resources, including all six WAV files and 94 OBJ mesh parts. This verifies JS/resource packaging, not Xcode compilation or ARKit behavior.
- Android native release compilation passed using JDK 17, Gradle 8.14.3 and Expo 54 / React Native 0.81.4 / Viro 2.52.0. The initial native build took 24 minutes 19 seconds while dependencies and native build outputs were prepared. Its debug-key v2 APK signature verified.
- Initial emulator launch exposed that an APK advertising x86_64 lacked Viro's renderer for that ABI. Archive inspection confirmed Viro provides ARM64/ARMv7 binaries only. A packaging regression test reproduced the missing-library problem; the Android configuration now restricts the build to ARM64.
- ARM translation then exposed SoLoader choosing an unavailable direct-APK library path. Extracted native-library packaging corrected startup. Both emulator GPU modes initially rejected Viro's mandatory sRGB surface; inspection of its two Java surface factories confirmed they did not retry. The Android prebuild plugin supplies factories with a default-colorspace fallback, preserving the native renderer binaries. The archive-patch check verifies removal of the replaced classes, retention of other classes and native libraries, and idempotence.
- The software GPU subsequently hit a 256-vector shader uniform limit. The hardware GPU rendered successfully after the surface fallback. Final studio checks used Android 14 / API 34, 720 × 1600, ARM translation, host Intel Iris Xe graphics, and disabled host audio.
- All six native studio flows passed: select, place, load every mesh, light, finish, retain spent remnants, and clear. `tools/qa_android.py` drives the installed standalone app with adb/UIAutomator. `dist/qa-results.json` contains results and `dist/screenshots/` contains eighteen placed/burning/spent captures. Wall times in the report include automation overhead, not measured audio duration.
- Screenshots were inspected for floor orientation and burn-down. Chakri, ladi and phuljhadi lie flat; the anar retains a visibly altered shell. Initial overexposure was corrected by reducing scene lighting. The audio readiness gate now polls native status as well as the native playback clock, preventing a missed SDK load event from leaving the Light button disabled.
- A final compatibility review confirmed that `HorizontalUpward` is [Android-only in the Viro plane API](https://viro-community.readme.io/docs/viroarplane). The iOS path uses `Horizontal`; Android retains `HorizontalUpward`. A failing/passing platform contract test covers the selection. The iOS bundle was exported again after this correction.
- The delivery APK was rebuilt after the platform correction and an all-axis sky-burst direction correction. Fresh native smoke runs covered sutli and then the final sky-shot build; `dist/qa-smoke.json` records the final build's checksum. Its v2 APK signature verifies. All six mastered WAV checksums were found unchanged in the APK, and all 23 native renderer library checksums were unchanged by the Java fallback patch.

World-tracked AR was not exercised on this emulator: ARCore reported unavailable. Studio checks do not prove floor-anchor stability or camera integration. iOS native compilation, signing, installation, physical listening, and iPhone X / AR-capable Android testing remain incomplete. No physical phone is attached. The iOS source targets a compatible OS version and its JS/resources bundle passes; no installable IPA is being represented as tested or complete.

The Expo/Apple signing route and an optional unsigned GitHub cloud-Mac workflow with Windows sideload instructions are documented in README.md. No Expo login or token was present on this workstation. No source was uploaded, cloud workflow executed, or signing identity created.
